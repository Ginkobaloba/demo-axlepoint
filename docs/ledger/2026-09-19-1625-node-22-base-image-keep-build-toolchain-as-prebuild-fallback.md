# 2026-09-19 16:25 CDT - Node 22 base image, keep build toolchain as prebuild fallback
- **Who:** Claude Sonnet 5 (session_01WAuS4DA21vazVZe9XMXuAw)
- **Change:** Dockerfile moved from node:20-bookworm-slim to node:22-bookworm-slim in all three stages (node 20 is EOL, team standard is node 22). The apt-get install of python3/make/g++ in the deps stage was first removed, then restored, in the same PR (#27).
- **Why:** better-sqlite3@12.10.0 ships a prebuilt binary for node 22 linux-x64 (ABI 127), proven by a clean docker build with the toolchain removed and a throwaway container serving 200 on /. But the identical experiment against the lumen-analytics sibling repo hit a prebuild-install network timeout on its first attempt, with no compiler to fall back to, and failed outright; an unchanged retry then succeeded. A prebuild is an optimization, not a dependency, and a build that fails on a flaky network is worse than a slightly larger builder stage. The toolchain was restored and confirmed to live only in the deps/build stages, never copied into the runtime image (the run stage only takes .next/standalone, .next/static, public, and data from the build stage, no node_modules).
- **State after:** demo-axlepoint's Dockerfile is on node:22-bookworm-slim with the apt toolchain kept as a fallback. docs/demos/axlepoint/decisions.md D-013 records the same reasoning. PR #27 open, not merged.
- **Refs:** PR #27 (Ginkobaloba/demo-axlepoint), docs/demos/axlepoint/decisions.md D-013, lumen-analytics PR #39 (same change, same reasoning, cross-repo evidence for the fallback decision)
